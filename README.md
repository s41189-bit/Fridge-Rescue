
# Fridge Rescue
智慧冰箱剩食推薦與保鮮管家

**目前版本：V2.0｜A、B、C 整合測試版**  
**最後更新：2026/11/17**

## 一、專案介紹

Fridge Rescue 是一個以「先看冰箱，再決定料理」為核心概念的互動式工具網站。

使用者可以記錄冰箱中的食材、數量與保存期限，再根據現有庫存取得食譜推薦、查看缺少的食材、產生採買清單，並在完成料理後手動更新庫存。

本專案希望降低日常下廚的決策成本，提高既有食材的使用機會，並協助減少食物浪費。

### 網站使用流程

1. 建立個人冰箱庫存
2. 查看保存期限及即期提醒
3. 取得智慧食譜推薦
4. 使用條件篩選與料理抽籤
5. 查看智慧補貨建議
6. 將缺少的食材加入採買清單
7. 完成料理並手動更新庫存
8. 根據更新後的庫存重新推薦料理

目前 V2.0 已整合三位組員的主要成果，具備上述核心操作流程。

本版本已完成主要功能開發及部分實際瀏覽器測試，仍需進行團隊完整驗收與正式部署確認。

## 三、V2.0 已實作功能

### 3.1 個人冰箱管理

- 新增食材。
- 選擇 30 種預設食材。
- 輸入食材數量。
- 根據食材主檔自動顯示單位。
- 設定或修改到期日期。
- 顯示保存期限狀態。
- 刪除單筆庫存。
- 清空冰箱。
- 載入示範庫存。
- 使用 localStorage 保存資料。
- 支援同一食材建立不同庫存批次。
- 保留沒有設定數量的舊資料。

例如：

- 雞蛋：6 顆
- 番茄：2 顆
- 吐司：4 片

若舊資料沒有數量欄位，網站會顯示「數量未設定」，不會自行假設為 1。

### 3.2 保存期限提醒

依照使用者輸入的到期日顯示不同狀態：

| 狀態 | 判定標準 | 食譜配對 |
|---|---|---|
| 綠燈 | 剩餘 4 天以上 | 可參與配對 |
| 黃燈 | 剩餘 0–3 天 | 可參與配對，並作為即期優先資訊 |
| 紅燈 | 已過期 | 不參與配對 |
| 灰色 | 未設定到期日 | 可參與配對 |

日期格式無效的資料不參與配對。

保存期限判斷只反映輸入日期，不代表食品安全鑑定。

### 3.3 智慧食譜推薦

網站目前使用 C 提供的 30 道食譜資料。

每道食譜包含：

- 食譜名稱
- 料理時間
- 料理難度
- 飲食分類
- 必要食材
- 建議份量
- 料理步驟

系統根據冰箱中可用的食材種類計算匹配度。

**匹配度公式：**

匹配度 = 已具備的必要食材種類數 ÷ 全部必要食材種類數 × 100%

結果四捨五入為整數百分比。

例如，番茄起司烘蛋需要：

- 雞蛋
- 番茄
- 起司

若冰箱只有雞蛋及番茄：

匹配度 = 2 ÷ 3 × 100% ≈ 67%

注意：匹配度只計算食材種類，不代表實際數量足夠。

### 3.4 食譜排序

目前推薦排序會考慮：

1. 必要食材是否全部具備
2. 即期食材及到期急迫程度
3. 食材匹配比例
4. 料理時間
5. 食譜 ID

目的在於優先呈現較容易使用目前冰箱食材完成的料理，並提高即期食材的使用機會。

### 3.5 食譜條件篩選

支援以下條件：

**料理時間**
- 不限
- 10 分鐘以內
- 20 分鐘以內
- 30 分鐘以內

**料理難度**
- 不限
- 簡單
- 中等
- 困難

**飲食偏好**
- 不限偏好
- 葷食
- 蛋奶素
- 全素

飲食偏好依照 C 的食譜標籤進行篩選，不自行推論其他飲食分類。

**零採買模式**

只顯示所有必要食材種類均已具備的料理。

但即使顯示「零採買」，仍需自行確認食材實際數量是否足夠。

### 3.6 智慧補貨推薦

系統會尋找目前只缺少一種必要食材的料理。

例如：

「補買起司，可額外解鎖 2 道料理。」

補貨統計使用完整食譜資料，不受畫面上的料理時間、難度或飲食篩選限制。

相同食材會合併統計，避免重複顯示。

### 3.7 採買清單

使用者可以將食譜缺少的食材加入採買清單。

目前支援：

- 一鍵加入缺少食材
- 相同食材自動去重
- 勾選已購買
- 刪除單筆項目
- 清空採買清單
- 複製文字清單
- 複製功能的手動備援
- localStorage 保存採買狀態

採買清單與冰箱庫存分開管理。

勾選「已購買」不會自動將食材新增到冰箱，避免在未確認數量及到期日的情況下產生不正確的庫存。

### 3.8 料理抽籤機

使用者可以點擊「今天吃什麼？」按鈕，從目前符合篩選條件的食譜中隨機抽選一道料理。

抽籤與食譜列表共用：

- 料理時間
- 料理難度
- 飲食偏好
- 零採買模式

抽籤結果使用既有的食譜詳情視窗。

如果沒有符合條件的食譜，系統會顯示提示訊息。

### 3.9 完成料理與手動更新庫存

V2.0 新增完成料理後的庫存管理功能。

操作流程：

1. 開啟匹配度 100% 的食譜詳情。
2. 點擊「完成料理／更新庫存」。
3. 查看必要食材的庫存批次。
4. 輸入各批次實際使用的數量。
5. 確認更新。
6. 系統扣除數量，並移除已用完的批次。
7. 重新計算食譜匹配度與智慧補貨結果。

**主要保護規則：**

- 不依食譜文字自動推算扣除數量。
- 不自動扣除所有必要食材。
- 批次使用數量可設為 0，表示不使用。
- 不允許超過原有庫存數量。
- 已過期或日期無效的批次不可扣除。
- 數量未設定的批次不可直接扣除。
- 按下取消不修改庫存。
- 確認後才儲存資料。
- 扣除完成後重新計算推薦結果。

目前此功能操作的是網站內建冰箱庫存。

使用外部 `FridgeRescue.setInventory()` 接入資料時，更新庫存按鈕不會直接寫回外部資料來源。

## 六、如何使用網站

### 6.1 開啟網站

可使用以下方式：

1. 開啟 GitHub Pages 測試網站。
2. 或在本機開啟 `index.html`。

請確認所需的 JavaScript 與 CSS 檔案位於同一專案目錄。

### 6.2 新增食材

1. 在「我的冰箱」選擇食材。
2. 輸入數量。
3. 確認自動顯示的單位。
4. 視需要設定到期日期。
5. 點擊「新增食材」。

食材新增後，推薦結果會立即重新計算。

### 6.3 查看料理推薦

網站會顯示：

- 匹配度
- 已具備食材
- 缺少食材
- 即期食材資訊
- 料理時間及難度

點擊「食譜詳情」可查看建議份量及料理步驟。

### 6.4 產生採買清單

1. 找到尚缺少食材的料理。
2. 點擊「加入採買清單」。
3. 查看合併後的缺少食材。
4. 使用勾選、刪除、清空或複製功能。

### 6.5 完成料理

1. 選擇必要食材種類齊全的料理。
2. 開啟食譜詳情。
3. 點擊「完成料理／更新庫存」。
4. 輸入實際使用數量。
5. 確認更新庫存。

系統不會自行決定扣除數量，應由使用者根據實際料理情況輸入。

### 6.6 示範資料

點擊「載入示範」可建立：

| 食材 | 示範數量 |
|---|---|
| 番茄 | 1 顆 |
| 雞蛋 | 6 顆 |
| 吐司 | 2 片 |

若已有庫存，載入前會要求確認是否覆蓋。

注意：示範資料僅供網站測試，並不代表特定食譜的建議用量。

## 七、本機資料保存

網站使用 localStorage 保存資料。

### 儲存項目

| localStorage Key | 內容 |
|---|---|
| fridgeRescue_A_mock_v1 | 冰箱食材庫存 |
| fridgeRescue_A_shopping_v1 | 採買清單 |

V2.0 保留原本的 Key，避免單純升級版本就讓舊資料失去讀取來源。

### 使用注意事項

- 不需要登入或註冊。
- 資料儲存在目前瀏覽器的網站儲存空間。
- 不同裝置及瀏覽器不會自動同步。
- 清除瀏覽器網站資料可能造成紀錄消失。
- 使用相同網站及瀏覽器設定檔的使用者可能共用紀錄。
- 本機開啟的 `index.html` 與 GitHub Pages 不會自動同步資料。
- 將程式碼推送至 GitHub 不會一併上傳使用者的 localStorage 紀錄。

### 舊資料相容性

舊版庫存可能只包含：

- id
- ingredient_id
- expiryDate

V2.0 可以讀取上述資料，並將缺少的數量視為 `null`。

這類資料顯示為「數量未設定」，不會自行轉換成 1。

舊資料相容性仍列入團隊後續完整驗收項目。

## 八、食材與食譜資料規格

### 8.1 食材資料

每筆食材主檔包含：

```javascript
{
    ingredient_id: "ING_021",
    ingredient_name: "雞蛋",
    unit: "顆",
    category: "蛋奶豆製品",
    suggested_days: 14
}
```

建議單位來自 B 的食材主檔。

單位只作為日常記錄方式，不代表標準重量或固定容量。

### 8.2 冰箱庫存

目前內部庫存格式範例：

```javascript
{
    id: "batch_001",
    ingredient_id: "ING_021",
    ingredient_name: "雞蛋",
    category: "蛋奶豆製品",
    expiryDate: "2026-11-23",
    quantity: 6,
    unit: "顆"
}
```

同一食材可以有不同 ID 的庫存批次。

### 8.3 正式食譜

C 的食譜資料例如：

```javascript
{
    id: "recipe-01",
    name: "番茄炒蛋",
    time_minutes: 10,
    difficulty: "簡單",
    diet: ["蛋奶素"],
    required_ingredients: ["番茄", "雞蛋"],
    portions: "1–2 人份（雞蛋 2 顆、番茄 1 顆）",
    steps: [
        "番茄洗淨切塊，雞蛋打散。",
        "將雞蛋與番茄分別炒熟後拌炒。"
    ],
    image: "images/recipe-01.jpg"
}
```

上例僅示意資料結構，正式料理步驟以 C 的原始 `recipes-c.js` 為準。

### 8.4 食譜轉換

A 的核心推薦系統使用：

```javascript
{
    recipeId: "recipe-01",
    name: "番茄炒蛋",
    cookingTime: 10,
    difficulty: "簡單",
    dietTags: ["蛋奶素"],
    requiredIngredients: ["ING_001", "ING_021"],
    portions: "1–2 人份（雞蛋 2 顆、番茄 1 顆）",
    steps: [],
    image: ""
}
```

`recipe-adapter.js` 負責轉換欄位及必要食材 ID。

目前正式圖片尚未接入，因此轉換後的 `image` 暫時為空字串，避免顯示不存在的圖片路徑。
